### Issue Summary
API requests to `/v1/orders` return 401 Unauthorized ("Demo token rejected.") after password change.

### Reproduction Steps
curl -X GET "https://api.internal.local/v1/orders" \
  -H "Authorization: Bearer demo-expired-token"

### Expected Result
HTTP 200 OK with resource representation.

### Actual Result
HTTP 401 Unauthorized (Response: {"error": "unauthorized", "message": "Demo token rejected."}).

### Diagnostic Evidence & Hypothesis
Observed fact: demo-expired-token returned 401. A 401 alone does not prove password revocation.
Subsequent test with demo-valid-token returned 200 OK.
Hypothesis: Password update invalidated prior active token credentials per KB-AUTH-101 playbook.
